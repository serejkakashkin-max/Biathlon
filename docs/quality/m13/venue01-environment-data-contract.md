# Venue01 environment data contract v1

This is presentation data derived from authoritative venue geometry. It must not change track/range tuning, hit geometry, motion, physical occupancy, weather simulation or route distance. Root owns Unity consumption and visual acceptance. The generator/checker sources are tracked under `scripts/content/m13`; output root is parameterized.

Every route corridor has one `widths_m` entry per knot, including its terminal knot. At an exact interior segment boundary, width samples the following segment; the terminal Reject-mode coordinate samples the last segment even for a closed loop. This matches `TrackSampler`, not an edge-count array.

`environment.json` contains `schema_version:1`, stable `id`, `venue_id`, resource references for manifest/track/visual, terrain, separate route corridors, explicit forest groups, range banks, assets/native mesh placements, simplified crowd and lighting. Its source geometry hashes are recorded in the audit. Individual physical loops always retain separate knot arrays; unrelated endpoints must never become a connecting ribbon or terrain edge.

Terrain bounds and tile centers are world XYZ. Tile `size` is world X/Z with Y0. `columns`/`rows` count vertex samples. A `height_resource` contains `{schema_version:1,id,venue_id,tile_id,columns,rows,heights_m:[...]}`. Heights are world Y, row-major Z then X, covering the tile from its lower X/Z corner at equal spacing. Adjacent tiles share exact samples. Terrain triangles use the same diagonal as the serialized verifier; forest Y is barycentric interpolation of those triangles.

Mass-only source samples nearest actual Main edge Y, preserves its full width plus4 m, then blends over100 m toward the Main-derived basin height profile. Format source adds actual Sprint/Pursuit branch edges to the nearest-course selection and expands bounds from all actual knots. Every physical loop is protected in forest placement even when it is not a hill-height source. The full stadium/range/target/penalty/start region stays flat with a40 m outer blend. The−0.03 m analytic surface offset alone does not protect full ribbon width: neighboring route heights and grid interpolation can protrude through lateral edges. Generation therefore caps affected grid triangles beneath every actual runtime ribbon triangle by the same authored3 cm offset, using exact triangle overlays and conservative shared-vertex lowering. Unaffected course-exterior cells keep their base profile; final tree Y uses corrected terrain. The independent verifier exposes full ribbon gap extrema. Runtime ribbon edge blending/skirts and weather readability require Unity inspection.

Each forest group references `{schema_version:1,id,venue_id,group_id,instances:[{id,position:{x,y,z},scale,yaw_deg,density_rank,species}]}`. Positions are world XYZ, not group-local offsets; `forest.instance_space` is `world`. Species are only `fir`/`pine`. Density rank lies in[0,1); every group respects the canonical native768 instance limit. Native mesh AABBs, scale and visual wind excursion plus an authored3 m margin define complete canopy/corridor exclusion. The complete firing/stadium apron is separately excluded. Group center has actual local terrain Y.

`range.banks` derive from the thirty canonical `VenueAuthoringPlan.MatPoint` positions plus `Range.Forward * TargetGeometry.DistanceMeters` plus canonical stadium target height. Forward is independent of skiing tangent. Bank local +Z follows explicit range forward; faces look toward local−Z. Runtime may update stance and closed mask from detached shooting snapshots. Bank positions and mat dimensions must be checked against Domain/canonical resources; serialized environment data is not an independent shooting authority.

`assets` are unit-scale licensed prefab placements. `mesh_assets` are explicit mesh/material world placements for screen, banners, lodge and finish modules. The old composite G2 Event prefab has baked benchmark child offsets and must not be used as an unmodified event placement. Grandstands may use their existing SpectatorSeating. Crowd uses owner-approved simplified `Biathlon/Crowd` resources; restricted crowd source is not imported or referenced.

Lighting names actual resource/preset/weather/sky material plus visual wind and temperature. These are presentation selections. Existing source/license/de-branding/derivation records remain mandatory; the generator does not introduce new third-party assets. The52 native resource references are checked and hashed independently of their recipe labels.

`verify_environment.py` re-reads serialized arrays and checks terrain borders, every tree's triangle height and full canopy/corridor/apron clearance, every target's canonical geometry and every actual runtime ribbon/terrain triangle-overlap extremum, including lateral edges and interiors. Its PASS establishes those static data facts. It is not FPS/GPU evidence, accepted-motion validation, race completion, final visual acceptance or owner approval.
