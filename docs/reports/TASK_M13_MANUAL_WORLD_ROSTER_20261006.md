# TASK M13 — fixed-tick manual world roster ledger

Date: 2026-10-06. Intermediate manual-steering integration; M13/WP-175–178 remain OPEN.

`ManualWorldRosterLedger` owns a stable ordered athlete roster, accepted world poses/velocities and selected-route progress cursors. For one fixed tick it validates that every trajectory starts at the accepted pose/velocity, uses the accepted route window and finishes at the configured tick duration. It then runs the shared body/course sweep and bounded route-credit preview into private scratch. Only a **fully clear** common interval for every athlete creates a one-use proposal. `Commit` publishes the entire roster and advances the tick together. A contact, course edge or phase station cap leaves the accepted roster and tick unchanged for a new trajectory/contact response; it never converts a partial prefix into a paid stationary tick. Stale or replaced proposals cannot commit. The exact solver/route contexts, ordered athlete IDs and tick frequency are bound in `manual_full_clear_world_roster_v1`.

This is an event-free **world/route ledger**, not the race transaction. It does not compute physical ski odometer distance, physiology, shooting, range/penalty traversal, lap/finish events or replay. It deliberately rejects a contact interval requiring continuation instead of simulating an artificial wait. The next integrator must resolve that interval and submit a newly proven full tick. The playable host still executes v1 route-following commands; owner-visible manual steering is not claimed.

Tests cover whole-roster atomic commit, blocked pair and range cap, stale/foreign state, single-use proposal, no warm allocations after replacing boxed struct equality, and two exact 25-tick world/route traces.
