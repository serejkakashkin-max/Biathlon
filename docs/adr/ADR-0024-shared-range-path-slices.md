# ADR0024 — shared range aisles and physical path slices

2026-10-01. TASK169A/B/C; prerequisite for WP169 Venue01. Contract/map implemented; live race integration pending. Extends ADR0011/0014/0017 without changing their v1 fixtures or replay contexts.

The old equal-length independent branch model has one common fork and one scalar firing coordinate. It cannot represent a real side-entry distribution aisle and individual mat stops safely. Assigning different loop IDs to overlapping aisle geometry would hide collisions from same-loop occupancy; removing the exclusive common guard alone is unsafe.

Production range paths are ordered slices of existing physical loops. The shared entry aisle retains the main-loop identity until the selected local fork. Each private mat path has an authored anchor; outgoing traffic uses slices of the same shared exit-aisle loop. Every lane's physical slice lengths sum exactly to the replaced canonical route interval. For entry width W and identical private path distance D: x_i + D + (W - x_i) = W + D. The final-lap bypass must also have W + D actual distance. Every world seam and crossing still requires geometric/admission acceptance.

The versioned PhysicalRangePathDefinition binds exact track/junction/connection snapshots, ordered unique lane IDs, whole-millimetre slice endpoints and directed seams. Mat stop distance is derived from cumulative slice lengths and the physical mat anchor. It must lie inside the logical range entry/exit interval. No redundant firing tuning field is stored. Different private curvature, width, snow and terrain data is allowed in the contract, so the subsequent integrator must consume actual physical samples.

PhysicalRangePathMap exposes read-only MapRoute, SampleRoute, DistanceToNextBoundary and FiringRouteNanometers. It preserves exact incoming/outgoing ownership, shared physical identities, and final-lap bypass. Boundary queries split both terrain segments and physical slices. Context records exact source snapshots and policy IDs. These methods confer no assignment or admission and are not wired into the approved playable race yet. RacePathMotion has an optional preview adapter that uses actual samples and splits at slice boundaries; it explicitly rejects a shooting traversal until individual stop integration exists.

TASK169D/E extends this prerequisite: an optional fixed-path athlete adapter and immutable per-bout personal stop now drive accepted shooting/penalty traversal using actual terrain. Motion requires the identical map association as the traversal. Receipts explicitly validate one physical slice and exact cumulative travel; zero-distance receipts retain their outgoing origin. Source buffers count terrain overlaps per slice occurrence, including repetitions. No field/pack factory selects the path yet; dynamic lane/path publication remains a separate prepared transaction. The earlier TASK169ABC rejection describes that checkpoint's state.

TASK169F adds optional preallocated same-layout choices to the athlete adapter. Owned revision-bound preparation stages a separate traversal before the earliest fork, preserving the accepted source state and ordinary-main body coordinate. Lane, path and personal stop publish together only on accepted positive travel reaching the common logical entry; cancellation and pre-entry prefixes publish nothing. Per-bout locks prevent a next-bout choice from changing a previous exit. PhysicalRangePathAssigned records the committed ordinal. Repeated scripted choices prove deterministic frames/events; replay reconstruction of external choice commands is not implemented by this adapter.

Next integration must use the selected actual sample in drafting and project pack receipts through the same slices; preserve incoming tails and continuous body occupancy. Width control must follow actual corridor width with gradual lateral motion. Mass Start later-bout ordering must use accepted fractional arrival time on the common admission line, with stable tie-break and no ordinal consumption on rejected previews. Every crossing needs a local conflict region rather than a single exclusive30-port entrance. The session choice API does not reserve a pack ordinal or establish body admission.

TASK169G introduces an isolated accepted-arrival receipt/order coordinator. The crossing is the first integer retimed fraction whose floor sample reaches the common line (ceiling interpolation); the complete receipt chain, including its suffix, must validate. First-bout lanes retain grid start ordinals; later bouts order by accepted fraction with start-ordinal ties. Counters, assignments, source receipts and clock remain scratch until owned commit. This does not establish physical admission. The future field must supply final accepted motion, verify source athlete/clock/bout/line, re-prepare actual paths after changed ordinals, and jointly validate all athlete/path/order handles before publication. External-decision replay integration remains pending.

TASK169H1 adds a cold complete layout association to the independent field. One exact physical map/track/route/definition family supplies all paths and cloned choice arrays to every entrant; authored lane IDs replace synthetic IDs only when the option is supplied. Context includes junction/connection snapshots once, as those captured source fields are absent from the path definition's ToJson. Fixed/default independent field races and persisted command-tape replay can use the binding. The shared Pack constructor explicitly rejects it before constructing a field until its traces, drafting, corridor control and joint admission are integrated. No shared-body proof follows from the independent field.

The two-lane contract fixture deliberately has no world geometry. It proves schema/map arithmetic and shared occupancy identity only. No production venue, no queue-free dense race, and no visual upgrade is claimed by TASK169A/B. Full30-athlete repeated Mass Start, occupied mats, concurrent penalty traffic, replay determinism and visual captures remain required before WP169 completion.

TASK169H2 integrates the complete layout into the shared pack. The field reuses its exact physical map, builds actor/path projections before the clock starts, samples accepted paths for drafting and AI, and projects prepared paths for continuous body queries. Actual corridor widths replace the global minimum only in this optional branch. Gradual lateral work remains paid; an inward move can be accepted while forward travel is stopped at a narrowing. The corridor check includes the longitudinal body envelope across an upcoming private fork, so a wide lateral line cannot push the front body into a narrower branch. Incoming seam footprints retain their exact lateral position until cleared.

This increment conservatively supports one incoming footprint per athlete. Cold validation requires successive route loop changes, including neighboring shooting laps, to be separated by the body half-length plus a maximum-speed tick bound. That bound includes source receipt capacity to cover per-substep nanometre rounding. Short connected paths require a future multi-footprint adapter rather than discarding an uncleared body. No guard or body is silently reduced.

For ordered Mass Start paths, the common logical admission line must precede every private fork by more than that maximum tick bound. Body resolution and precision fallback run first on the identical shared prefix. The field then extracts final accepted arrivals, prepares the owned order batch, re-prepares newly selected paths with the same commands and accepted travel caps, and checks every timed receipt and movement value for exact equality. It revalidates all athlete/order handles, fractional boundaries, widths and body sweeps before joint publication. Empty order batches advance only their committed clock. Rejected or replaced trajectories consume no ordinal. Local forks/crossings remain exclusive physical regions; the common logical line is not a global conflict gate.

These optional paths do not alter the null-layout legacy field context or numerical policies. Two-athlete complete fixed/ordered bouts establish adapter behavior; production world geometry, dense admission, venue content and visual acceptance remain separate WP169 requirements. Shooting equations and difficulty tuning are unchanged; OWNER-FEEL-001 remains for its scheduled review.
