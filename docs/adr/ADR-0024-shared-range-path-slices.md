# ADR0024 — shared range aisles and physical path slices

2026-10-01. TASK169A/B/C; prerequisite for WP169 Venue01. Contract/map implemented; live race integration pending. Extends ADR0011/0014/0017 without changing their v1 fixtures or replay contexts.

The old equal-length independent branch model has one common fork and one scalar firing coordinate. It cannot represent a real side-entry distribution aisle and individual mat stops safely. Assigning different loop IDs to overlapping aisle geometry would hide collisions from same-loop occupancy; removing the exclusive common guard alone is unsafe.

Production range paths are ordered slices of existing physical loops. The shared entry aisle retains the main-loop identity until the selected local fork. Each private mat path has an authored anchor; outgoing traffic uses slices of the same shared exit-aisle loop. Every lane's physical slice lengths sum exactly to the replaced canonical route interval. For entry width W and identical private path distance D: x_i + D + (W - x_i) = W + D. The final-lap bypass must also have W + D actual distance. Every world seam and crossing still requires geometric/admission acceptance.

The versioned PhysicalRangePathDefinition binds exact track/junction/connection snapshots, ordered unique lane IDs, whole-millimetre slice endpoints and directed seams. Mat stop distance is derived from cumulative slice lengths and the physical mat anchor. It must lie inside the logical range entry/exit interval. No redundant firing tuning field is stored. Different private curvature, width, snow and terrain data is allowed in the contract, so the subsequent integrator must consume actual physical samples.

PhysicalRangePathMap exposes read-only MapRoute, SampleRoute, DistanceToNextBoundary and FiringRouteNanometers. It preserves exact incoming/outgoing ownership, shared physical identities, and final-lap bypass. Boundary queries split both terrain segments and physical slices. Context records exact source snapshots and policy IDs. These methods confer no assignment or admission and are not wired into the approved playable race yet. RacePathMotion has an optional preview adapter that uses actual samples and splits at slice boundaries; it explicitly rejects a shooting traversal until individual stop integration exists.

Next integration must use the selected actual sample in physiology/posture, each ski boundary substep and drafting; project receipts through the same slices; set each bout's mat stop transactionally with lane assignment; preserve incoming tails and continuous body occupancy. Width control must follow actual corridor width with gradual lateral motion. Mass Start later-bout ordering must use accepted fractional arrival time on the common admission line, with stable tie-break and no ordinal consumption on rejected previews. Every crossing needs a local conflict region rather than a single exclusive30-port entrance.

The two-lane contract fixture deliberately has no world geometry. It proves schema/map arithmetic and shared occupancy identity only. No production venue, no queue-free dense race, and no visual upgrade is claimed by TASK169A/B. Full30-athlete repeated Mass Start, occupied mats, concurrent penalty traffic, replay determinism and visual captures remain required before WP169 completion.
