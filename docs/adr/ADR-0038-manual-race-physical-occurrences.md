# ADR-0038 — Explicit physical occurrences for manual race movement

2026-10-08. Accepted observation prerequisite under ADR-0028/0033/0037.
Live manual race integration remains OPEN.

`ManualRacePathCatalog` binds the exact track, route, requirements, competition,
visual geometry, selected immutable mat path and optional simultaneous-start
approach. It describes a positive physical interval on an existing loop for each
occurrence. Counted flow covers the exact base race distance: range slices replace
their original interval, split exactly at the personal firing anchor. Penalty
entry and counted entry-to-rejoin travel are separate boundaries. The final
non-shooting lap keeps its ordinary route geometry.

Start travel and each possible penalty circuit have their own physical arc.
They map to a fixed base-route coordinate and cannot add base competition distance.
Each bout and penalty ordinal has a separate occurrence even when world coordinates
repeat. Shared exit slices keep the same physical loop identity across athletes;
individual mat loops remain distinct. Catalog order is not transition admission.
Firing, penalty decisions/circuits and finish are explicit gates. No debt, hit,
mat choice, checkpoint, event or accepted state is generated by a query.

The existing local projector/corridor/tube implementation is reused through an
internal physical-scope factory. Scoped stations live in an independent geometry
namespace. This factory cannot satisfy `IsBoundTo(baseRoute)`; the base-world
ledger rejects it. Public catalog observations/targets expose physical arc and a
separately named mapped competition coordinate. Queries search one selected
occurrence only, never a nearest lap or an automatic successor. Surface sampling
uses that occurrence's actual loop/local coordinate, including backward movement.

The zero-width endpoint test found a real encoding problem at a shared approach
end: floating edge station arithmetic could skip its edge during binary search,
and quantized world coordinates could observe just inside the exact endpoint.
Scoped queries apply the existing two-nanometre encoding reserve to the seek and
endpoint observation. They do not move the world pose or enlarge body clearance.
This policy is recorded separately in scoped context. The existing base-route
query policy/context remain unchanged.

Validation: sixteen new tests pass in Unity, including exact zero-width endpoint
projection/sampling, both end lanes and all three production formats, repeated
penalty identity, correct surface metadata, foreign-context rejection and zero
warm query allocations. Final focused .NET selection including legacy replay:
69/69 PASS. Earlier failing endpoint receipts and intermittent allocation failures
are preserved. The broader allocation risk has not been resolved by a later pass.

Next: phase-owned cursors and admitted world transitions, mixed moving/stationary
roster ticks, contact/surface continuation, actual session lifecycle/events,
complete manual replay, host input and presentation. This catalog does not
certify private-path body clearance or complete M13; no Windows build is produced.

## 2026-10-08 — scoped high-water progress and ordinary handoff

`ManualRacePathProgression` now proposes event-free per-occurrence high water.
Backward observed arc remains backward; returning to an already reached point
does not credit it again. A start/penalty high-water increase cannot add base
distance. The maximum admitted arc remains supplied by the owning race phase.
An actor frame is an observation, not a continuous body/movement proof.

Ordinary handoff requires an accepted cursor at the exact endpoint and the same
world pose observing both endpoints of the ordered successor. It keeps base
credit and does not advance the clock, odometer or pose. Firing, penalty access,
penalty-circuit and finish gates are closed in this API. High water at the end
while the actual accepted body is behind it is insufficient. A future full
world/session transaction must separately authorize those lifecycle transitions.

The exact catalog, actor, occurrence and pose/observation binding are checked.
Group proposals validate every row before writing any destination slot. Current
group proposals belong to one catalog; the heterogeneous world roster still
needs to combine individually owned lane proposals with all-body clearance.
Ten new .NET and ten native tests PASS; combined catalog/progression26/26 PASS.
Live authoritative race output, replay and the playable host are unchanged.

## 2026-10-08 — heterogeneous full-clear world roster

`ManualScopedWorldRoster` owns accepted world pose/velocity, scoped cursor and
physical odometer for a complete stable roster. Each actor can have a different
assigned catalog, but catalogs must share the same exact route/profile objects.
Stationary and moving actors participate in the same all-pair body check. Each
actor then checks its own selected physical course and admitted arc limit.

Only a full-clear fixed interval can produce an owned proposal. A body/contact
prefix, unproved course start, mismatched source or phase limit changes no
accepted actor/clock/odometer and invalidates an earlier uncommitted proof.
The diagnostic attempt distinguishes these causes. There is no fallback that
turns a rejected proposal into a paid standing tick. This is not contact
continuation: the future world runner must resolve/advance that prefix inside
the same tick, not pause the race when this primitive returns false.

Force trajectories retain their exact distance; contact trajectories use the
existing fixed64-panel velocity-norm integral and frozen directional grade.
All initial scoped coordinates, pose, velocity, odometer, speed and clock are
captured immutably with body/contact/course context. Ordinary roster handoffs
validate all requested rows before changing any accepted occurrence, keeping
the same world motion and clock. Lifecycle gates remain closed.

Eight new tests PASS in .NET and native Unity; combined scoped selection34/34
PASS. The mixed runtime fixture covers start plus base movement with different
mat selections. It does not qualify full traffic, private mat/penalty body
clearance, continuous phase transitions or a playable manual race. The initial
contact-test gap was corrected to derive from the actual unchanged occupied
envelope; its failing receipt remains. Sessions/replay/host remain unwired.

## 2026-10-08 — centre portals are separate from course end caps

A physical body can fit inside a round tube endpoint cap while its centre has
crossed an unadmitted occurrence. Clamped arc observation cannot prove admission.
The scoped world now activates local start/upper centre planes for whole visual
edges covered by its selected tube window. Continuous signed-distance bounds
use existing trajectory numerical reserves and sweep work limits; broad curved
terminal windows may require interval/window refinement. Distant planes do not
constrain the middle of a closed penalty circuit. Rejection is provisional,
never a paid standing tick. Policy v2; body/course/tuning and live host unchanged.
Endpoint red retained; .NET87/87 and native16/16 PASS including internal-cap
out-and-back, long-edge/narrow-window and inward/tangential endpoint cases.
